# YouTube 下载 + 抽帧

粘贴网址下载 YouTube 视频，下载完直接选中抽帧。浏览器界面 + 命令行两种用法，
运行环境（Python 3.12 / yt-dlp / ffmpeg）全部打包在文件夹内，不依赖 Homebrew。

## 快速开始

```bash
# 首次安装（已装好则跳过）
bash 安装环境.sh
```

然后双击 `启动下载器.command`，浏览器会自动打开界面。

## 文件说明

| 文件 | 作用 |
|---|---|
| `启动下载器.command` | 双击启动网页版界面 |
| `下载.command` | 双击启动命令行版 |
| `安装环境.sh` | 重装运行环境（换电脑时用） |
| `app.py` | 本地 HTTP 服务 + 下载/抽帧调度 |
| `extract.py` | 抽帧内核：媒体探测、时间点计算、ffmpeg 调度 |
| `ui.html` | 网页界面（下载 / 抽帧两个标签页） |
| `cli.py` | 命令行版下载器 |
| `使用说明.txt` | 面向使用者的完整说明 |

## 功能

**下载**

- 单条 / 批量网址，自动排队，同时最多 2 个下载
- 画质 8K~480p 可选，或仅下音频（MP3 / M4A / WAV）
- 兼容模式输出 H.264 + AAC 的 MP4，Mac 和剪辑软件直接可用
- 中英文字幕（含自动字幕）转 SRT、封面图、整个播放列表
- 支持从浏览器读取 Cookie，下载会员 / 年龄限制 / 私享视频
- 支持 HTTP 代理
- 实时进度、速度、剩余时间，可取消

**抽帧**

- 四种方式：按间隔 / 定帧数 / 按 FPS / 关键帧（I 帧），算法与原 `视频抽帧.html` 一致
- 下载完的视频自动出现在列表里，下载任务上有「去抽帧」直接跳转
- HDR → SDR 色调映射（HDR 片源自动开启）
- 输出 PNG / JPEG / WebP，可限制最长边
- 基于实测解码速度给出耗时预估，抽帧中有实时进度、可取消
- 抽完直接在页面里看缩略图网格，可点开原图

## 实现要点

**客户端自动回退**：YouTube 按客户端指纹拦截请求，默认客户端常报
`The page needs to be reloaded`。工具会依次尝试
`默认 → android_vr → tv → ios → web_safari → mweb`，
命中即用；遇到 `Private video`、`members-only` 等确定无解的错误则直接失败，
不浪费时间轮询。

**格式表达式**：兼容模式下用 `bv*[vcodec^=avc1]+ba[acodec^=mp4a]` 锁定 H.264/AAC，
并逐级降级到 `bv*+ba` 和单文件格式，避免选不到流直接报错。
非兼容模式画质不限编码，但音轨同样优先 `ba[acodec^=mp4a]`——YouTube 默认给的是
Opus，装进 MP4 后 QuickTime 放不出声音。
注意 yt-dlp 把 `A+B/C` 解析为 `(A+B)/C`，所以每个候选必须是完整表达式再用 `/` 串联，
在 `+` 右边嵌 `/` 会让选择器直接退化成只下音频。

**文件名带画质**（`... [id] 2160p.mp4`）：否则同一个视频换画质重下会因为同名
被判定成「已下载」而静默跳过。

**环境隔离**：系统自带 Python 是 3.9，而 yt-dlp 2026 版要求 3.10+。
用 `uv` 拉一份独立 Python 3.12 到 `.venv`，ffmpeg 走 `imageio-ffmpeg` 的内置二进制，
全程无需 sudo，不污染系统。

**自动更新**：YouTube 接口变动频繁，启动器每次启动会在后台静默升级 yt-dlp。

### 抽帧部分

**HDR 必须做色调映射**：HDR 片源（PQ / HLG 传输曲线）直接抽帧会得到灰白发雾、
几乎没有对比度的图，这也是浏览器 canvas 抽帧的通病。这里用
`zscale=t=linear → tonemap=hable → zscale=t=bt709` 转成 SDR，探测到
`smpte2084` / `arib-std-b67` 时自动开启。注意只有 `bt2020` 色域标记不算 HDR，
不需要映射。

**I 帧靠读容器索引，不解码**：`-skip_frame nokey` 会被 AV1 解码器忽略，
实测拿一个 10 分钟 4K AV1 的 I 帧列表要 11 分钟以上（等于软解了全片）。
这里改成直接解析 MP4 的 `stss` / `stts` / `ctts` 算出 I 帧时间，
同一个文件从 11 分钟降到 0.00 秒。非 MP4 容器兜底用 `-discard nokey`
（在解封装层丢包，不是解码层，对 AV1 同样有效）。

**两种执行策略按密度选**：单程解码要把整段范围全解一遍；逐点定位每帧要从最近的
关键帧解到目标帧，成本约半个 GOP。所以帧稀疏时逐点更快——实测 4K AV1 从 0-60s
每 5 秒抽一帧，单程 214 秒，逐点 29 秒。判据是 `帧数 × 平均GOP < 范围时长`。

**耗时预估靠实测**：不同片源解码速度差两个数量级（1080p H.264 几百 fps，
4K AV1 软解约 10 fps），只有选中视频时真跑一小段测一下，才能给出有意义的预估。
VideoToolbox 对这个 AV1 片源实测没有加速（28.7s → 26.1s），所以没启用硬解。

**fps 滤镜的边界**：`-to end` 时 fps 滤镜会丢掉最后一个采样点，导致实得比
界面预估少一帧。解决办法是多放一个步长再截，抽完按计划帧数裁掉多余的文件。
